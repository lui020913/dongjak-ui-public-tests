# 공개 프런트엔드 — 정밀 UI/UX 품질 감사 v1.0

이 문서는 [DESIGN_LANGUAGE.md](DESIGN_LANGUAGE.md)의 **Modern Civic Minimalism**을 실제 점검·수정·회귀 검증으로 연결하는 운영 체크리스트입니다. **대상은 공개 UI 작업실**이며 비공개 원본 앱 코드·서버·API·GIS·Production을 직접 수정하는 권한이 아닙니다. UI 프로토타입에 존재하지 않는 기능은 `NOT IMPLEMENTED`로 기록하고, 실서비스 기능 통과로 간주하지 않습니다.

## 0. 작업 순서 / 우선순위

1. 시작할 때 지정된 공개 프런트엔드 브랜치, 진행 중 PR, 최근 CI, 미해결 이슈와 직전 검증 SHA를 확인합니다. 다른 자동화 작업의 코드와 충돌하면 중단·조정합니다.
2. 매 회 1개 디바이스군(모바일·태블릿·PC)에서 실제 재현 가능한 연관 결함 최대 3개를 선정합니다. 수정 최대 2회/회차. 완료된 부분을 재수정하지 않습니다.
3. 심각도는 **P0** 기능 중단·화면 불가·배포 보안, **P1** 터치 불가·중요 가림·데이터 오인, **P2** 정렬·가독성·상호작용 불일치, **P3** 작은 디자인 결함 순입니다.
4. 전후 캡처 + DOM 좌표·계산 CSS + 재현 단계 + 검사 결과를 저장합니다. 검증 불가능한 영역은 `UNVERIFIED`, 재현되지 않은 항목은 `NOT REPRODUCED`로 구분합니다.
5. 기존 앱 기능·색상 콘셉트를 유지하고 접근성 표시를 단순 미관 이유로 제거하지 않습니다. `npm run check`, `npm run build`, `npm run test:e2e`와 관련된 신규 검사에 실패하면 Preview 승격 금지. 패치 파일·작업 PR·다음 정확한 이어받기 지점 기록.

## 2. 반드시 기록할 정량 정보

- **레이아웃:** 뷰포트·DPR·orientation, document overflow, 핵심 요소 bounding-box(x/y/width/height), UI 겹침/잘림 여부, 글꼴 배율.
- **스타일:** 불필요한 border/outline/box-shadow의 실제 원인과 수정 전후 CSS; 의도적 focus ring은 유지.
- **인터랙션:** 사용한 기기군, 클릭 또는 포인터 이동 거리, 단계 변화와 실패 동작, 키보드 접근 경로.
- **모션:** 실제로 수집한 frame interval 분포·Long Task 또는 Layout Shift 표본, 분석 환경과 반복 횟수; 측정하지 못하면 수치를 상상해서 채우지 않음.
- **결과:** baseline SHA, 새 SHA, 파일 목록, 테스트 대상/개수, 통과·실패·실행 안 함의 구분, 공개 Preview URL과 실제 배포 SHA, 다음 우선순위.

**성능 수치 관리:** 60Hz의 16.7ms는 단일 프레임 예산(렌더링 외 다른 작업도 공유)이며 보장 FPS가 아닙니다. Long Task >50ms는 분석 신호입니다. LCP/INP/CLS 등은 실제 사용자 측정 또는 적절한 계측 범위 내에서만 평가합니다. 일회성 Chromium CI 결과를 iOS 실사용 성능이나 운영 API 응답으로 일반화하지 않습니다.

## 3. 자동화 실행 전략

- **매시간 단위:** 이전 회차 이어받기 + 영향도 높은 결함 1~3개 개선 + 영향받는 해상도/상태 집중 회귀 검사. 변화가 없으면 커밋·배포를 만들지 않습니다.
- **기준 변경/핵심 레이아웃 수정 시:** 기존 필수 8개 해상도, 라이트/다크, 닫힘/반열림/전체열림, 지도 조작, 키보드/터치, 확대·축소, reduced-motion, 캡처 회귀를 한 번씩 수행합니다.
- **확장 검증(가능할 때):** 320px와 breakpoint 전후, 태블릿 회전, 고DPR/120~200% 텍스트, 저성능 CPU 시뮬레이션, 오프라인·지연, 브라우저별 차이, 기능별 성능 추적. 실행하지 않은 항목을 통과로 표기하지 않습니다.
- **보고:** `P0/P1/P2/P3` 결함 목록과 스크린샷 위치, 재현·원인·수정·검증 수치, 보류 조건을 PR/Actions Summary에 남깁니다.

## 4. Production 격리

공개 UI 시제품과 기존 운영 지도는 별개입니다. 공개 UI 작업 브랜치의 `src/main.js`·`styles.css`를 운영 앱으로 직접 복사하지 않습니다. 기존 승인된 경로에서 `frontend/production/dongjak-production-overlay.css`의 허용된 **안전한 CSS 일부**만 별도 검사·통합 게이트가 검증할 수 있으며, 공개 자동화는 비공개 저장소를 읽거나 변경하지 않습니다. Production 승격 성공은 해당 배포의 실제 실행 결과와 사후 검증으로만 인정합니다.
