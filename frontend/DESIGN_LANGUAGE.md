# 동작하는 안전지도 — 디자인 언어 v1.0

**Modern Civic Minimalism**: 공공 보행안전 지도 서비스에 적합한 신뢰감, 가독성, 지도 중심 조작성을 우선하는 디자인 언어입니다.

> 적용 범위: 공개 저장소의 독립 UI 작업실 `frontend/`만. 이 문서는 원본 비공개 앱/Production 디자인의 변경 승인이 아닙니다. 기존 기능, 실제 GIS/교통/AI API, 로그인은 건드리지 않습니다.

## 1. 변경 불가 원칙

1. **Map-first** — 지도가 주인공입니다. 도구·패널은 필요한 순간에 노출하며 검색·지도 조작을 가리지 않습니다.
2. **Clarity before decoration** — 기능의 중요도, 계층, 버튼 상태가 색상 효과보다 먼저 전달되어야 합니다.
3. **Existing green brand** — 기존 녹색 브랜드 및 밝은 아이보리 배경을 유지합니다. 새로운 파란색/보라색 테마로 임의 교체하지 않습니다.
4. **Consistent geometry** — 한 줄의 요소는 공통 수직 기준선과 베이스라인을 공유합니다. 아이콘·텍스트 시각 중심 정렬을 화면 캡처로 검증합니다.
5. **Motion with meaning** — 애니메이션은 화면 계층 변화와 열기/닫기 방향을 설명해야 합니다. 애니메이션 장식화와 과도한 블러·유리효과는 피합니다.
6. **Never break working flows** — UI 개선 과정에서도 기존 반응형 화면, 키보드 조작, 스크롤 및 지도 상호작용을 유지합니다.

## 2. 디자인 토큰 (코드 기준)

모든 신규·수정 UI는 `src/design-tokens.css`의 `--ds-*` 토큰을 재사용합니다. 기존의 `--surface`, `--ink`, `--accent` 등의 별칭은 점진적으로 토큰에 연결하되 기존 모양을 갑자기 변경하지 않습니다.

| 용도 | 라이트 / 값 | 다크 / 값 |
| --- | --- | --- |
| 브랜드 강조 | `#197253` | `#74d4aa` |
| 브랜드 약한 배경 | `#e3f2e9` | `#294d3d` |
| 서피스 | `#ffffff` | `#202e28` |
| 서브 서피스 | `#f3f8f4` | `#283c32` |
| 본문 | `#1e3028` | `#f1f7f2` |
| 보조 텍스트 | `#68796f` | `#aec3b4` |
| 테두리 | `#dce7df` | `#3a5142` |

- 폰트: **Pretendard 우선**, Apple SD Gothic Neo → Noto Sans KR → Inter → system fallback. 폰트 다운로드/라이선스와 실제 브라우저 적용은 별개로 검증합니다.
- 간격: 4px 그리드(`4, 8, 12, 16, 20, 24, 32px`)를 기본으로 하고, 불필요한 빈 공간과 밀도를 실측합니다.
- 라운드: 컨트롤 12px, 검색 15px, 패널/시트 22px. 현행 요소별 차이는 기능을 유지하며 단계적으로 통일합니다.
- 그림자: 정보 계층을 구분할 정도로만 사용; 부유형 요소 외 무분별한 그림자 금지.
- 모션: 짧은 상태 전환 약 200~220ms, 바텀시트 약 320ms. 단계별 펼침과 축소는 양방향으로 자연스럽게 연결해야 하며 `prefers-reduced-motion`을 존중합니다.
- 터치: 신규 주요 인터랙션은 가능하면 **44×44 CSS px 이상**의 누를 수 있는 영역을 확보하고, 밀집된 지도 도구에는 간격과 실제 히트박스를 함께 점검합니다. 현재 36~39px 컨트롤 등은 추후 개선 대상이며, 기준을 충족했다고 주장하면 안 됩니다.

## 3. 화면별 구성 원칙

- **모바일 375 / 390 / 430px:** 검색이 가장 먼저 보이도록 하고, 화면 상단 액션은 검색 또는 브랜드와 충돌하지 않도록 배치합니다. 바텀시트는 closed/half/full 전환과 역방향 드래그가 모두 작동해야 합니다. 안전 영역(safe-area inset)을 유지합니다.
- **태블릿 768 / 1024px 및 가로 모드:** 모바일을 단순 확대하지 않습니다. 측면 탐색과 작업 패널의 정렬, 지도 도구의 비가림, 가로·세로 전환을 별도로 검증합니다.
- **데스크톱 1280 / 1440 / 1920px:** 좌측 메뉴·중앙 검색·우측 지도 도구의 정렬 체계와 패널 폭을 독립적으로 최적화합니다. 패널을 여는 동안 지도 조작이 유지되어야 합니다.

## 4. AI 자동 수정의 평가 순서

1. 최신 공개 작업 브랜치·Draft PR·미해결 항목·동시 작업을 확인합니다.
2. PC·태블릿·모바일의 **실제 캡처와 DOM 경계 좌표**를 수집합니다. 캡처 없이 시각적 문제를 추정만으로 수정하지 않습니다.
3. 레이아웃 깨짐/겹침 → 정렬/가독성 → 패널과 터치 상호작용 → 색상/타이포그래피/모션 순으로 영향도를 평가합니다.
4. 한 작업군에서 연관된 결함 1~3개를 수정하고 전후 캡처를 비교합니다. 같은 화면을 반복 정리하기보다 다른 작업군의 개선도 순환합니다.
5. `npm run check`, `npm run build`, Playwright 반응형/상호작용 테스트를 실행하고 커밋 SHA, 변경 파일, Preview URL, 성공/실패/보류 사유를 기록합니다.
6. **통과한 공개 UI Preview만 갱신**합니다. 공개 프로토타입을 기존 Cloudflare Production과 동일시하지 않으며 실서비스 자동 승격은 별도 통합·회귀 검증·롤백 준비 후에만 합니다.

## 5. 완료 판정

디자인 언어가 정의되었다는 사실만으로 디자인이 완성된 것은 아닙니다. 완료 판정은 실제 해당 해상도에서의 전후 스크린샷, 키보드·클릭·터치 테스트, 레이아웃 겹침 여부, 현재 작업 대상 커밋의 CI 통과를 기반으로만 합니다.

## 6. 세부 정밀 QA 기준

간격·경계·모션 성능·접근성·테마·브레이크포인트·모바일 터치·PWA·지도 조작의 전체 감사 범위, 심각도 분류, 검증 증빙은 [QUALITY_AUDIT.md](QUALITY_AUDIT.md)에 정의합니다. UI 자동화는 이 기준을 참고하되 한 회에 결함 1~3개씩 다루고 검증되지 않은 항목을 통과로 보고하지 않습니다. `tests/precision-audit.spec.mjs`는 주요 화면의 기하정보 및 다크모드 증빙, 모션 감소 동작을 검사하는 첫 자동화 점검입니다.
