# 패치 대체·삭제 정책 (2026-11-21)

## 원칙

**신형 패치가 구형 패치를 완전히 대체하면, 같은 PR에서 구형 패치의 실행 코드와 연결 지점을 반드시 삭제합니다.** 구형 패치 위에 신형 패치를 덧씌우는 CSS/JS 오버라이드는 금지합니다. 사용자가 가장 최근에 승인한 디자인과 동작을 기준으로 합니다.

단순히 파일명이 `v8xx`처럼 오래됐다는 이유만으로 삭제하지 않습니다. 구형 파일 내부에 독립적인 지도 데이터, 인증, API 대체 처리 등 현재도 필요한 기능이 남아 있으면 그 부분은 보존하거나 공용 모듈로 옮깁니다.

## 변경 PR 필수 항목

| 항목 | 확인·조치 |
| --- | --- |
| 대체 범위 | 구형·신형 파일별 기능 매핑, 100% 대체 여부 확인 |
| 삭제 | 불필요한 CSS 선언, 중복 `!important` 및 선택자, JS 이벤트 리스너/초기화 함수, 컴포넌트, 스크립트, 불필요한 리소스 |
| 참조 정리 | `main.js` 등의 `import`, `index.html` script/link, 번들 빌드 주입, 플래그, 워크플로 등 모든 참조 제거 |
| 상태 관리 | 하단탭 및 바텀시트당 활성 컨트롤러 하나만 유지. 중복 타이머·커튼·페이드 이벤트 제거 |
| QA | 구형 디자인 기대치 제거, 최신 디자인 회귀 테스트 재작성. 테스트 통과를 위해 잘못된 시각효과를 정당화하지 않음 |
| 배포 | 최신 `main` 기반 단일 후보 → Preview 스크린샷·동작 검증 → Production. 이미 종료된 이전 패치의 재주입 금지 |

## 첫 정리 시점 확인 대상 (대체 확정 전 삭제 금지)

- `frontend/production/mobile-next.css`: 누적된 초고우선순위 선택자 및 여러 세대의 버튼·환승역 스타일
- `frontend/production/mobile-next.js`: 출발/도착 SVG 삽입 및 그 외 DOM 보정 기능의 중복 여부
- `app/src/bottom-tab-navigation.js`: 화면 커튼·퇴장·등장 효과 및 타 모듈의 전환 제어와 중복 여부
- `app/src/main.js`: 버전별 스타일 import와 활성 초기화 함수, build injection 결과
- `app/src/mobile-compact-transport-sheet.js`: 소형 지하철·버스 정보창에서 도착정보의 가시성
- `app/src/fixed-rail-lines.js`, `app/src/rail-official-shapes.js`: 개략 선형과 공식 GIS 선형의 대체/폴백 관계 (기능적 폴백이므로 무조건 삭제 금지)
- `app/tests/v9269-flat-surfaces.test.mjs`: 예전 평면형 버튼/불투명 표면을 요구하는 디자인 테스트 계약

## 완료 판정

1. 최신 기능·디자인이 구형 코드 없이 동작합니다.
2. 잔존 코드 검색에서 삭제하기로 한 규칙, 초기화 함수, import 및 패치 재주입 지점이 0건입니다.
3. 대표 모바일 기기에서 페이지 전환 시 지도가 노출되지 않고 애니메이션이 겹치지 않습니다.
4. 작은 지하철 정보창에서 도착정보 또는 API 이용 불가 상태가 명확히 보이며, 호선·출발/도착·즐겨찾기 아이콘이 승인된 사양과 일치합니다.
5. 회귀 테스트와 Preview QA가 통과하고, 승인된 Production 배포까지 검증됩니다.
