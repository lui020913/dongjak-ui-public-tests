# Community moderation rollout
1. Apply additive `community_moderation.sql`; this does not block old client writes. Deploy `community-moderation` Edge Function with JWT verification. Existing production remains unchanged until cutover.
2. Configure server-only `GEMINI_API_KEY` and `COMMUNITY_MODERATION_MODEL` in Supabase Edge Function Secrets. Do not copy them into source code or chat. Confirm actual model access and data-handling terms; update privacy notice. External AI receives public content and attached images (not precise coordinates, account identifiers or keys).
3. Test coordinated enforcement on staging; the function fails closed unless all four restrictive policies are present. Verify allowed, removed, review, duplicate, image OCR, API failure, RLS and appeals. Production cutover: deploy compatible mobile client with protection gate `community_moderation_enforce.sql`; old public write clients will then be rejected (local records still work). No deploy until verified. 
4. Admin dashboard: Table Editor → community_moderation_queue/appeals; SQL Editor → `select public.community_moderation_finish('<queue UUID>','published','clean');` for approve, or `...('removed','profanity')` for remove; appeals `select public.community_moderation_review_appeal('<appeal UUID>',true);` / false. Restore inserts a new published row; if parent post was deleted or payload purged, review manually. Dashboard admin only. No admin role is granted to normal users.
5. Text rate limit: 8 attempts/minute; repeated normalized text within 10 minutes, and identical byte hash after three accepted/pending uploads, detects spam. Similar images are not guaranteed detected. Ambiguous/safety-filtered results go to private review. No automated account suspension, push alert or retention purge yet. Select retention period before launch. Existing published content is not retrospectively reviewed.

6. Apply `community_extras.sql` for account-only bookmarks, one-level replies, reports, and the updated finish RPC. Reports are administrator review requests, not automatic deletion or emergency service reports. Saved list loads up to 200 bookmarks; public feed loads recent 50. `kind: status` checks configuration and enforcement, not actual model access. Sharing uses a deep link only for public posts. Browser in-app alerts, not system push. User-posted comment text and images are subject to the same AI transfer notice.

7. Apply `community_moderation_limits.sql` before deploying v3. A 64-bit server-side difference hash (max Hamming distance 5) detects near duplicates; a fourth similar photo within 10 minutes goes to manual review, never automatic deletion solely for perceptual similarity. Exact duplicates use previous rules. Three final removals in 24 hours trigger a temporary 30-minute public-writing restriction measured from the last removal; approved appeals immediately stop counting. Reads and local records stay available. This is an initial operational policy and should be tuned after observing false positives. Images are limited to bounded JPEG decoding (2 MP, 32 MiB decode budget). No operating-system push registration yet.

8. Before activating enforcement, invoke community-moderation with the Supabase dashboard's service-role Authorization and JSON `{ "kind": "admin-probe" }`. Only that privileged token can run the fixed synthetic text, image and violation cases. No real posts, account records, secret values or raw model output are returned. `model_ok: true` is required; the normal user status route only checks configuration. Never paste a service-role token into chat or the app.

9. PWA push setup: apply `community_push.sql`, deploy `community-push` with JWT verification, configure server-only `COMMUNITY_PUSH_VAPID_PUBLIC`, `COMMUNITY_PUSH_VAPID_PRIVATE`, `COMMUNITY_PUSH_VAPID_SUBJECT` (operator email as mailto URI). Set a recurring Supabase Cron invocation of `community-push` with service-role Authorization and body `{ "kind":"dispatch" }` using a securely stored Vault credential. Until the VAPID and cron configuration and real-device test are verified, background delivery is not enabled. Users explicitly opt in from the community notice list. Subscription secrets and delivery queue have no user SELECT/INSERT grants; receiver endpoint allowlisted, redirects disabled. Lock-screen notifications contain no post text or moderation reason. Browser unsubscribe on logout. Native Android APK is separate (requires FCM registration and device testing); iOS web push requires a supporting installed home-screen web app. Foreground notice polling remains independent.
