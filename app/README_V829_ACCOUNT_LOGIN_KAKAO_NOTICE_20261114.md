# 동작하는 안전지도 v8.2.9 — 로그인 후 계정 표시 및 카카오톡 로그인 알림(선택)

기준: v8.2.8 `DongjakApp_FULL_v8.2.8_KAKAO_OAUTH_DIAGNOSTICS_20261113.zip`

## 로그인 후 화면

- `내 기록`의 아이콘에 로그인 여부를 표시합니다(초록 점은 Supabase 세션이 있는 경우에만 표시).
- `내 기록` 상단 `내 계정` 카드에 표시 이름, 이메일, 카카오 연동 계정 여부 및 동기화 상태를 보여줍니다.
- `계정 관리`에서 기존 내 정보 / 보안 설정 / 연결된 계정 / 로그아웃을 유지합니다.
- 로그인 후 화면은 실제 Supabase `getSession()` 및 `onAuthStateChange()` 결과에 기반하며, 카카오 로그인 페이지를 보았다는 이유만으로 로그인 성공 표시를 하지 않습니다.

## 카카오톡 로그인 알림 — 중요한 제약

**카카오의 '나에게 메시지 보내기' API를 이용한 선택 기능**입니다. `동작하는 안전지도` 카카오톡 채널이 보낸 '알림톡'이 아닙니다. 카카오톡 **나와의 채팅**에 고정된 로그인 메시지를 보냅니다.

### 사전 설정(사용자/앱 관리자)

1. https://developers.kakao.com/console/app 에서 로그인에 사용하는 **동일 카카오 앱**을 엽니다.
2. `카카오 로그인 → 동의항목 → 접근권한`에서 **카카오톡 메시지 전송(`talk_message`)**을 사용 설정합니다. 일반 로그인과 별도의 동의입니다. 사용 권한 제한이 있다면 안내된 신청/심사 절차를 진행해야 합니다.
3. 동의 목적 예시: `사용자가 로그인 알림 수신을 선택한 경우, 카카오톡 나와의 채팅으로 동작하는 안전지도 로그인 사실을 알리기 위해 사용합니다.`
4. 필요 시 카카오 앱 `제품 링크 관리 → 웹 도메인`에 `https://dongjak-walk-safety-preview.pages.dev`를 등록합니다. 기존 Supabase OAuth 콜백 URI 및 Client ID 설정은 변경하지 않습니다.
5. 지도에서 **기존 카카오 계정으로 로그인**한 뒤 `내 기록 → 계정 관리 → 보안 설정 → 카카오톡 로그인 알림`을 켭니다. 기본값은 꺼짐입니다.
6. 다음 **카카오 로그인을 새로 수행했을 때** 추가 `talk_message` 동의를 요청하고, 로그인 성공 시 사용자 본인의 나와의 채팅에 메시지를 **한 번만** 전송합니다. 단순 페이지 새로고침/토큰 갱신이나 이메일·비밀번호 로그인에는 전송하지 않습니다.
7. 카카오에서 별도 동의가 거부되면 로그인 자체가 실패할 수 있습니다. 그런 경우 기존 세션으로 다시 접속해 알림을 끈 후 카카오 로그인을 재시도합니다. 알림 사용 여부를 끄더라도 즐겨찾기에는 영향이 없습니다.

### 기술적 구성

- 브라우저는 **별도 동의가 활성화된 경우에만** `scopes: 'talk_message'`로 Supabase Kakao OAuth를 요청합니다.
- Supabase가 OAuth 콜백에서 발급한 `provider_token`은 메모리에서 한 번만 읽고 Cloudflare Pages Function `/api/account/login-notification`으로 같은 출처 요청을 보냅니다. 토큰은 **로컬 스토리지와 데이터베이스에 저장하지 않습니다**.
- 함수는 카카오 `POST https://kapi.kakao.com/v2/api/talk/memo/default/send`로 고정 문구를 전달합니다. 임의의 수신자, 전화번호, 사용자 작성 내용을 지원하지 않습니다.
- 로그인·DB 저장에는 기존 Supabase 설정을 그대로 사용합니다. 신규 SQL은 없습니다.
- **실제 카카오 메시지 전송은 이 ZIP만으로 확인한 것이 아닙니다.** 관리자 권한/`talk_message` 동의/카카오 토큰/Cloudflare Pages 실제 배포 후 별도 확인해야 합니다.
- 공개 서비스에서는 로그인 알림에 대한 사용자별 발송 제한과 모니터링이 추가로 필요할 수 있습니다.

### iPhone 홈 화면 PWA 주의

카카오 OAuth 화면이 외부 Safari/인앱 브라우저에서 열리면서 **홈 화면 PWA와 다른 브라우저 저장소를 사용하는 경우** 로그인한 곳과 앱이 보는 세션이 다를 수 있습니다. v8.2.9는 실제 Supabase 세션 여부를 명확히 보여주지만, 운영체제의 브라우저 간 세션 전달을 자동 해결한다고 보장하지 않습니다. `내 기록`에서 여전히 로그인 전으로 보이면 로그인 완료 후 돌아온 주소와 실행 방식(홈 화면 PWA인지 Safari 탭인지)을 비교하여 OAuth 반환 경로를 별도로 조정해야 합니다.

## 설치/실행/배포

- **전체 ZIP**: 새 프로젝트 폴더로 압축 해제. 기존 `.env.local`, `.env.production.local`을 안전하게 옮기십시오. 비밀키는 사용하지 않습니다.
- **델타 패치**: 정확히 v8.2.8 소스에 `APPLY_PATCH.cmd` 실행. 파일 SHA-256 기준 검사·백업·실패 시 복구 포함.
- 코드 검증: `npm test` 그리고 `npm run check:release`.
- 로컬 개발: `npm ci` 후 `npm run dev`.
- Cloudflare: `npm run deploy:pages` (Pages Functions 포함 배포).

로컬 Vite 서버에서는 Cloudflare Function이 실행되지 않으므로 실제 카카오톡 전송을 확인하려면 **Cloudflare Pages 배포 후** 테스트하거나 적절한 Pages 로컬 개발 서버를 이용하십시오.
